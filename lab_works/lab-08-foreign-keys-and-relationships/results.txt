# Lab 08 — Foreign Keys and Relationships

## 1. Method 1: Inline Foreign Key

Command:

```sql
CREATE TABLE departments (
    dept_id SERIAL PRIMARY KEY,
    dept_name VARCHAR(100) NOT NULL,
    location VARCHAR(100)
);

CREATE TABLE employees (
    emp_id SERIAL PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    dept_id INTEGER REFERENCES departments(dept_id)
);
```

Output:

```text
CREATE TABLE
CREATE TABLE
```

The `\d departments` and `\d employees` commands confirmed the primary keys and the foreign key `employees_dept_id_fkey`.

## 2. Method 2: Table-Level Foreign Key

Created the tables using a table-level foreign key constraint.

Output:

```text
CREATE TABLE
CREATE TABLE
```

The `\d employees` command confirmed:

```text
Foreign-key constraints:
    "employees_dept_id_fkey" FOREIGN KEY (dept_id) REFERENCES departments(dept_id)
```

## 3. Method 3: Adding a Foreign Key to an Existing Table

Added a foreign key using `ALTER TABLE`.

```sql
ALTER TABLE employees
ADD CONSTRAINT fk_employee_department
FOREIGN KEY (dept_id) REFERENCES departments(dept_id);
```

Output:

```text
ALTER TABLE
```

The `\d employees` command confirmed:

```text
Foreign-key constraints:
    "fk_employee_department" FOREIGN KEY (dept_id) REFERENCES departments(dept_id)
```

## 4. Method 4: Named Constraint During Table Creation

```sql
CREATE TABLE employees (
    emp_id SERIAL PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    dept_id INTEGER,
    CONSTRAINT fk_employee_department
        FOREIGN KEY (dept_id)
        REFERENCES departments(dept_id)
);
```

```text
Foreign-key constraints:
    "fk_employee_department" FOREIGN KEY (dept_id) REFERENCES departments(dept_id)
```

## 5. Referential Integrity

Created three departments:

```text
dept_id | dept_name  | location
--------+------------+-----------
1       | Engineering| Building A
2       | Marketing  | Building B
3       | HR         | Building C
```

Inserted one employee:

```text
emp_id | first_name | last_name | dept_id
-------+------------+-----------+--------
1      | John       | Smith     | 1
```

### Testing an invalid foreign key

Attempted to insert an employee with `dept_id = 99`, which does not exist.

Output:

```text
ERROR: insert or update on table "employees" violates foreign key constraint "employees_dept_id_fkey"
DETAIL: Key (dept_id)=(99) is not present in table "departments".
```

### Testing deletion of a referenced department

Attempted to delete department 1 while John Smith still referenced it.

Output:

```text
ERROR: update or delete on table "departments" violates foreign key constraint "employees_dept_id_fkey" on table "employees"
DETAIL: Key (dept_id)=(1) is still referenced from table "employees".
```

The department and employee remained unchanged.

## 6. ON DELETE CASCADE

Created two departments and three employees.

Initial departments:

```text
dept_id | dept_name
--------+------------
1       | Engineering
2       | Marketing
```

Initial employees:

```text
emp_id | first_name | last_name | dept_id
-------+------------+-----------+--------
1      | John       | Smith     | 1
2      | Jane       | Doe       | 1
3      | Mike       | Brown     | 2
```

Deleted department 1.

Output:

```text
DELETE 1
```

Remaining departments:

```text
dept_id | dept_name
--------+-----------
2       | Marketing
```

Remaining employees:

```text
emp_id | first_name | last_name | dept_id
-------+------------+-----------+--------
3      | Mike       | Brown     | 2
```

John and Jane were automatically deleted because their department was deleted.

## 9. ON DELETE RESTRICT

Created department Engineering and employee John Smith, who referenced department 1.

Attempted to delete department 1.

Output:

```text
ERROR: update or delete on table "departments" violates foreign key constraint "employees_dept_id_fkey" on table "employees"
DETAIL: Key (dept_id)=(1) is still referenced from table "employees".
```

The department could not be deleted while the employee referenced it.

## 12. One-to-One Relationship

Created tables `users_lab8` and `user_profiles_lab8`.

The `user_profiles_lab8.user_id` column has both `UNIQUE` and `NOT NULL` constraints and references `users_lab8(user_id)` with `ON DELETE CASCADE`.

Inserted user:

```text
user_id | username | email             | created_at
--------+----------+-------------------+----------------------------
1       | johndoe  | john@example.com  | 2026-10-17 22:05:22.986187
```

Inserted profile:

```text
profile_id | user_id | first_name | last_name | bio
-----------+---------+------------+-----------+-----------------------------------------------
1          | 1       | John       | Doe       | Software developer passionate about databases
```

### Testing the UNIQUE constraint

Attempted to create a second profile for user 1.

Output:

```text
ERROR: duplicate key value violates unique constraint "user_profiles_lab8_user_id_key"
DETAIL: Key (user_id)=(1) already exists.
```

The `UNIQUE` constraint prevented the same user from having multiple profiles.

## Conclusion

The lab demonstrated:

- Four methods of defining foreign keys.
- Referential integrity and foreign-key constraint violations.
- `ON DELETE CASCADE`, `ON DELETE SET NULL`, `ON DELETE SET DEFAULT`, and `ON DELETE RESTRICT`.
- `ON UPDATE CASCADE` and combined cascade options.
- One-to-one, one-to-many, and many-to-many relationships.
- Using `JOIN` queries to retrieve related data.
- Using `UNIQUE` constraints to prevent duplicate profiles and duplicate student-course enrollments.
